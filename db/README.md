# База данных для парсера

Эта папка содержит файлы для работы с базой данных SQLite.

## Файлы
http://pf.loc/parser-fsa/api.php?action=get&count=5
Доступные эндпоинты API:
?action=get&count={N} - получить N свободных ID
?action=ok&id={ID} - отметить ID как использованный
?action=stats - получить статистику
?action=reset&id={ID} - сбросить статус (для тестирования)
Запустите тест и покажите результат!

- `install_db.php` - **Скрипт инициализации базы данных** (запустите первым!)
- `database.php` - Класс для подключения к базе данных SQLite
- `rb-mysql.php` - RedBean ORM для работы с базой данных
- `ids_gate.php` - PHP гейт для приема ID от парсера
- `stats.php` - Веб-интерфейс для просмотра статистики и управления базой

## Установка

### Автоматическая установка

1. Убедитесь, что у вас установлен PHP с поддержкой SQLite
2. Скопируйте файлы в папку `DB/`
3. Убедитесь, что файл `rb-mysql.php` (RedBean ORM) находится в той же папке
4. Запустите скрипт инициализации:

```bash
php install_db.php
```

Или через веб-браузер:
```
http://localhost/DB/install_db.php
```

Скрипт создаст:
- ✅ Базу данных `proxy_manager.db`
- ✅ Таблицу `parsed_ids` для хранения ID
- ✅ Таблицу `system_logs` для системных логов
- ✅ Таблицу `system_settings` с базовыми настройками
- ✅ Все необходимые индексы для быстрого поиска
- ✅ Лог установки `install_db.log`

### Ручная установка

Если автоматическая установка не работает, таблицы создадутся автоматически при первом обращении к гейту.

## Настройка

### 1. Веб-сервер

Убедитесь, что у вас запущен веб-сервер (Apache, Nginx или встроенный PHP сервер):

```bash
# Встроенный PHP сервер (для тестирования)
php -S localhost:8000 -t /path/to/your/project
```

### 2. Права доступа

Убедитесь, что папка `DB` имеет права на запись:

```bash
chmod 755 DB/
chmod 666 DB/*.db
```

### 3. URL гейта

В файле `parser.js` настройте правильный URL гейта:

```javascript
const databaseGate = new DatabaseGate('http://localhost/DB/ids_gate.php', writeLog);
```

Замените `localhost` на ваш домен или IP адрес.

## Структура базы данных

### Таблица `parsed_ids`

| Поле | Тип | Описание |
|------|-----|----------|
| id | INTEGER PRIMARY KEY | Автоинкрементный ID записи |
| declaration_id | INTEGER UNIQUE | ID декларации (уникальный) |
| source | VARCHAR(50) | Источник данных (по умолчанию 'parser') |
| date_added | DATETIME | Дата добавления записи |
| use_status | INTEGER | Статус использования (0 - не использован, 1 - использован) |
| created_at | DATETIME | Дата создания записи |
| updated_at | DATETIME | Дата обновления записи |

### Таблица `system_logs`

| Поле | Тип | Описание |
|------|-----|----------|
| id | INTEGER PRIMARY KEY | Автоинкрементный ID записи |
| level | VARCHAR(10) | Уровень лога (INFO, WARNING, ERROR) |
| message | TEXT | Текст сообщения |
| context | TEXT | Дополнительный контекст (JSON) |
| created_at | DATETIME | Дата создания записи |

### Таблица `system_settings`

| Поле | Тип | Описание |
|------|-----|----------|
| id | INTEGER PRIMARY KEY | Автоинкрементный ID записи |
| setting_key | VARCHAR(100) UNIQUE | Ключ настройки |
| setting_value | TEXT | Значение настройки |
| description | TEXT | Описание настройки |
| created_at | DATETIME | Дата создания записи |
| updated_at | DATETIME | Дата обновления записи |

#### Базовые настройки

| Ключ | Значение по умолчанию | Описание |
|------|----------------------|----------|
| parser_enabled | 1 | Включен ли парсер |
| parser_delay | 3000 | Задержка между запросами (мс) |
| parser_max_pages | 10 | Максимальное количество страниц для парсинга |
| telegram_enabled | 1 | Включены ли уведомления в Telegram |
| database_auto_cleanup | 0 | Автоматическая очистка старых записей |
| cleanup_days | 30 | Количество дней для хранения записей |

## API гейта

### POST /DB/ids_gate.php

Отправляет массив ID для записи в базу данных.

#### Запрос

```json
{
  "ids": [20719094, 20719095, 20719096],
  "source": "parser"
}
```

#### Ответ

```json
{
  "success": true,
  "message": "Все ID успешно обработаны",
  "data": {
    "total_received": 3,
    "added": 2,
    "skipped": 1,
    "errors": 0,
    "error_details": []
  },
  "timestamp": "2025-01-14 15:30:00"
}
```

#### Коды ответов

- `200` - Успешно
- `207` - Успешно с ошибками (Multi-Status)
- `400` - Ошибка в запросе
- `405` - Неверный метод
- `500` - Внутренняя ошибка сервера

## Логирование

Гейт ведет лог в файле `DB/ids_gate.log` с информацией о:
- Полученных запросах
- Обработанных ID
- Ошибках
- Статистике

## Безопасность

- Гейт принимает только POST запросы
- Проверяется валидность JSON
- ID проверяются на числовой формат
- Дубликаты автоматически пропускаются
- Логируются все операции

## Веб-интерфейс статистики

### Доступ к статистике

Откройте в браузере: `http://localhost/DB/stats.php`

### Возможности интерфейса

- **Общая статистика**: количество записей, добавленных сегодня, вчера, позавчера
- **Статистика по источникам**: откуда пришли данные
- **Активность за 7 дней**: график добавления записей
- **Последние записи**: 10 последних добавленных ID
- **Статистика по месяцам**: данные за последние 12 месяцев
- **Статус использования**: сколько ID использовано/не использовано

### Очистка базы данных

1. Нажмите кнопку "Очистить базу данных"
2. Подтвердите действие
3. Все записи будут удалены (действие необратимо!)

### GET параметры

- `?action=clear` - Показать подтверждение очистки
- `?action=clear&confirm=yes` - Выполнить очистку базы

## Мониторинг

Для мониторинга работы гейта:

1. **Веб-интерфейс**: `http://localhost/DB/stats.php`
2. **Лог файл**: `ids_gate.log`
3. **SQL запросы** для анализа данных:

```sql
-- Общее количество записей
SELECT COUNT(*) FROM parsed_ids;

-- Статистика по источникам
SELECT source, COUNT(*) FROM parsed_ids GROUP BY source;

-- Статистика по датам
SELECT DATE(date_added) as date, COUNT(*) FROM parsed_ids GROUP BY DATE(date_added);

-- Неиспользованные ID
SELECT COUNT(*) FROM parsed_ids WHERE use_status = 0;
```

## Устранение неполадок

### Гейт недоступен

1. Проверьте, что веб-сервер запущен
2. Убедитесь в правильности URL в парсере
3. Проверьте права доступа к папке

### Ошибки базы данных

1. Проверьте права на запись в папку DB
2. Убедитесь, что SQLite поддерживается PHP
3. Проверьте лог файл на ошибки

### Дубликаты ID

Гейт автоматически пропускает дубликаты. Если нужно принудительно обновить запись:

```sql
UPDATE parsed_ids SET use_status = 0, updated_at = CURRENT_TIMESTAMP WHERE declaration_id = 20719094;
```

### Ошибка "Invalid bean type: parsed_ids"

Эта ошибка возникает, если таблица не создана. Решения:

1. **Запустите скрипт установки:**
   ```bash
   php install_db.php
   ```

2. **Или создайте таблицу вручную:**
   ```sql
   CREATE TABLE parsed_ids (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       declaration_id INTEGER UNIQUE NOT NULL,
       source VARCHAR(50) DEFAULT 'parser',
       date_added DATETIME DEFAULT CURRENT_TIMESTAMP,
       use_status INTEGER DEFAULT 0,
       created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
       updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
   );
   ```

3. **Проверьте настройки RedBean в database.php:**
   ```php
   R::freeze(false); // Разрешаем создание новых таблиц
   R::useFeatureSet('novice/latest'); // Используем последние возможности
   ```
